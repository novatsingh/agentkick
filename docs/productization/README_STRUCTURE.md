# README Structure

The README should sell the problem, show the command, and explain the product boundary quickly.

It should not become a full architecture document.

## Target README Flow

### 1. Name And One-Liner

```markdown
# AgentKick

The workflow operating system for AI-native software development.
```

### 2. Immediate Promise

```markdown
Run AgentKick before AI agents touch your repo.
```

### 3. Problem

Position against:

- chaotic vibe coding
- context overflow
- giant AI chats
- temporary chat memory
- repo confusion
- workflow fragmentation

### 4. Install And First Command

```bash
npx agentkick init
npx agentkick doctor
```

### 5. What It Creates

Short bullet list:

- `AGENTS.md`
- memory files
- workflow rules
- agent instructions
- Doctor readiness checks

### 6. Doctor Example

Show a compact terminal output.

### 7. What AgentKick Is Not

```text
Not an AI wrapper.
Not semantic search.
Not vector retrieval.
Not a code index.
```

### 8. Positioning

```text
Sverklo/codegraph-rust understand repositories.
AgentKick structures AI workflows around repositories.
```

### 9. Supported Agents

- Codex
- Claude Code
- Cursor
- Windsurf
- Copilot

### 10. Commands

Keep concise:

- `new`
- `init`
- `add`
- `doctor`
- `fix`
- `focus`

### 11. Docs

Link to:

- architecture
- memory
- Doctor
- context engine
- productization

### 12. Development

```bash
npm install
npm test
```

## README Tone

Use:

- direct claims
- concrete files
- terminal examples
- before/after workflow

Avoid:

- generic AI buzzwords
- grand future promises
- retrieval comparisons as enemies
- long spec text
- vague productivity claims

## GitHub Above The Fold

Above the fold should include:

- product one-liner
- install command
- one sentence of value
- Doctor example or generated file list

## README Success Criteria

A developer should understand within 30 seconds:

- what AgentKick is
- why it exists
- how to try it
- what files it writes
- what it is not
